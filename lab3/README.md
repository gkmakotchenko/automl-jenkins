# Интеграция Jenkins ⇄ GitHub

### Инструкция:
1. Jenkins должен быть доступен из интернета по HTTPS, чтобы GitHub мог отправлять webhooks. Для этого рекомендуется использовать доменное имя с корректно настроенным TLS-сертификатом, при этом домен должен указывать на адрес и порт, на котором работает Jenkins (по умолчанию 8080). Если Jenkins запущен локально или на виртуальной машине без публичного домена, можно использовать туннелирующие сервисы (например, ngrok или serveo). Инструкция для получения валидного, статичного доменного имени с помощью serveo:
    * Проверьте, что у Вас доступен ssh-клиент и сгенерированы ssh-ключи. Если ключей нет, следуйте [инструкции](https://selectel.ru/blog/tutorials/how-to-generate-ssh/).  
    * Введите команду ```ssh -R 80:localhost:порт_jenkins serveo.net```, проверьте доступность Jenkins по выданному в ответ доменному имени из интернета. (Важно! На данном этапе выданное доменное имя активно только до завершения ssh-сессии)
    * Если предыдущие этапы успешно выполнены, придумайте поддомен (домен третьего уровня) и выполните следующую команду: ```ssh -R ваш_поддомен:80:localhost:порт_jenkins serveo.net```. 
    * В ответ Вам все еще будет выдано случайное доменное имя, однако, вместе с ним будет инструкция, как зарегистрировать публичный ssh-ключ на специальном портале по ссылке подобной этой: "https://console.serveo.net/ssh/keys?add=SHA256...". После регистрации повторно запустите команду из предыдущего пункта и убедитесь в работоспособности вашего Jenkins по настроенному доменному имени. После завершите процесс в терминале (Ctrl + C).  
    * Запустите следующую команду: ```ssh -f -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -R ваш_поддомен:80:localhost:порт_jenkins serveo.net```, она позволяет туннелированию работать в фоне даже после завершения вашей ssh-сессии.  
    * Чтобы прервать фоновый процесс из предыдущего пункта, сначала найдите его PID с помощью ```ps aux | grep ssh```, затем ```kill найденный_PID```. Либо воспользуйтесь аналогичным инструментарием вашей операционной системы.
2. В настройках Jenkins (Settings -> System -> Jenkins Location) вставьте ваше доменное имя вида: "https://ваш-fqdn/".
3. Для того, чтобы неавторизованные пользователи могли смотреть подробную информацию о билдах вашего пайплайна необходимо:
    * В Settings -> Security -> Authentication выбрать тип авторизации "Project-based Matrix Authorization Strategy".
    * Для анонимных пользователей минимум должен быть выбран тип Read в разделах "Полные" и "Просмотр".
    * При создании пайплайна в разделе **Properties** выбрать "Enable project-based security" -> "Inherit permissions from parent ACL".
    * Для анонимов выбрать Read в разделе "Задача".
4. На стороне GitHub, в настройках репозитория необходимо перейти в раздел Webhooks и выбрать следующее:
    * **Payload URL:** "https://ваш-fqdn/github-webhook/"
    * **Content type:** application/json
    * Enable SSL verification
    * Let me select individual events: Pushes, Pull requests
5. В настройках вашего аккаунта GitHub, в разделе Personal Access Tokens необходимо создать Fine-grained token для вашего репозитория и в дальнейшем использовать его в качестве credentials в Jenkins пайплайне.
